Title: Trim spaces around a pet type name

Story: As a clinic administrator, I want spaces before and after a pet type name to be removed when I add or rename a pet type, so that the list does not show the same type twice with different spacing.

**Requires a new or changed contract from:** None

Expected behaviour:
- When a pet type is added (`POST /api/pettypes`), spaces at the start and end of `name` are removed before it is saved. The response returns the trimmed name.
- When a pet type is renamed (`PUT /api/pettypes/{petTypeId}`), spaces at the start and end of `name` are removed before it is saved.
- Spaces inside a name are kept (`"guinea pig"` stays `"guinea pig"`).
- A name with no spaces around it is saved exactly as sent.
- A `null` name is handled exactly as it is today. This story adds no new validation and no new error responses.
- The API contract (`src/main/resources/openapi.yml`) does not change.

Acceptance criteria:
- AC1: `POST /api/pettypes` with `"name": "  hamster  "` returns 201 and the returned pet type has `"name": "hamster"`.
- AC2: `PUT /api/pettypes/{petTypeId}` with `"name": "  dog "` returns 204 and the pet type is saved with the name `"dog"`.
- AC3: `POST /api/pettypes` with `"name": "guinea pig"` returns 201 and the returned name is `"guinea pig"`.
- AC4: The existing pet type controller tests still pass, with new tests for AC1 to AC3.

In scope:
- `src/main/java/org/springframework/samples/petclinic/rest/controller/v1/PetTypeRestControllerV1.java` (the add and update methods).
- Tests in `src/test/java/org/springframework/samples/petclinic/rest/controller/PetTypeRestControllerV1Tests.java`.

Out of scope: `openapi.yml`, the model and repository classes, the database schemas, every other controller, the Angular front end.
